srt: the right controls at the wrong layer

What it gave us

  • Filesystem and network limits on any process
  • Deny-by-default network via a host proxy

Where it fell short

  • Per process on one machine, not a K8s workload
  • Shares the host kernel

Great on a developer laptop, not a multi-tenant platform

Kubernetes SIG Apps

Agent-sandbox: isolated, but still a pod

What it gave us

  • A stateful pod with a stable identity
  • gVisor or Kata isolation

Where it fell short

  • One always-on pod per agent
  • Idle agents still hold compute

The isolation was right; the pod was still the unit

NVIDIA

OpenShell: keys out of reach, but always on

What it gave us

  • Deny-by-default egress, per binary
  • Keys swapped in at the proxy

Where it fell short

  • One always-on sandbox per agent
  • Egress enforcement runs inside the sandbox

Its credential model was right, and Substrate kept it

What bit us

Every runtime we tried isolated agents fine. But an idle agent kept its pod running, and stopping it lost everything in memory.

What we do now

Snapshot the whole sandbox, memory and files, and restore it in milliseconds. Substrate runs every actor in gVisor or a microVM, which can do exactly that.

Good to knowSubstrate’s demo fits about 250 stateful actors onto 8 pods.

Put every control outside the sandbox

What bit us

Anything inside the sandbox is reachable by a prompt-injected agent. A key in an environment variable is one “print your environment” away from leaking.

What we do now

A gateway the agent can’t touch holds the keys and decides where traffic may go. kagent’s Harness won’t accept a secret reference at all.

Good to knowThe gateway intercepts TLS, and only header-based auth works for model providers.

Identity follows the actor, not the pod

What bit us

A worker pod hosts a different actor every few minutes. Anything keyed to the pod, like a ServiceAccount, NetworkPolicy or log label, points at the wrong thing.

What we do now

Each actor gets its own short-lived SPIFFE identity, and policy and audit attach to the actor.

Good to knowA sandbox an agent creates over MCP belongs to the MCP identity unless you turn on token propagation.

A suspended agent is stored data

What bit us

Suspending idle agents saves a lot of compute. The snapshot left behind holds everything the agent had in memory.

What we do now

Treat the snapshot bucket like any store of sensitive data: encrypt it, set retention, and decide who can restore.

Good to knowPer-actor snapshot encryption is on Substrate’s roadmap; bucket-level encryption and access controls cover it today.

One snapshot holds

  • The agent’s memory
  • Tool output
  • Files it read
  • Its working state

Your sandbox runtime is now a data format

What bit us

A snapshot only restores on the runtime that wrote it. gVisor even needed a special flag before network connections survived a checkpoint.

What we do now

Substrate pins the exact gVisor binary into every template and snapshot, and we plan runtime upgrades like schema migrations.

Good to knowYou can’t casually bump gVisor under a fleet of suspended agents.
